## Story

**As a** usuário da calculadora,
**I want** digitar expressões como `3 + 4 * 2` ou `(1 + 2) * 3` e obter o resultado correto ao clicar `=`,
**so that** a calculadora respeite a precedência de operadores e parênteses, diferente de uma simples avaliação da esquerda para a direita.

## Acceptance Criteria

1. Clicar em botões numéricos e operadores acumula a expressão no display (`.expression`)
2. Clicar `=` avalia a expressão via `MathParser.evaluate()` e exibe o resultado em `.result`
3. A precedência é correta: `2 + 3 * 4` retorna `14`, não `20`
4. Parênteses funcionam: `(2 + 3) * 4` retorna `20`
5. O operador `%` calcula módulo: `10 % 3` retorna `1`
6. O operador `^` calcula potência: `2 ^ 8` retorna `256`
7. Divisão por zero exibe `Erro: divisão por zero` no display (sem travar)
8. Expressão malformada (ex: `++3`, `3 *`) exibe `Erro: expressão inválida`
9. Após um erro, o próximo clique em qualquer botão limpa o estado e começa nova expressão
10. `C` limpa toda a expressão; `CE` apaga apenas o último caractere digitado
11. O botão `()` insere `(` se o número de parênteses abertos for maior que fechados, caso contrário insere `)`
12. Resultado numérico com mais de 10 dígitos é exibido em notação científica (`1.23456789e+10`)

## Dev Notes

### Por que Shunting-Yard e não `eval()`?

`eval('2 + 3 * 4')` funcionaria, mas executaria **qualquer código JavaScript** — um risco de segurança (XSS). O algoritmo Shunting-Yard processa apenas tokens matemáticos reconhecidos e é seguro por design. Essa é uma regra inegociável da arquitetura.

### Estrutura de dados do tokenize

```javascript
// Entrada: "2 + 3 * (4 - 1)"
// Saída:
[
  { type: 'number',   value: '2' },
  { type: 'operator', value: '+' },
  { type: 'number',   value: '3' },
  { type: 'operator', value: '*' },
  { type: 'paren',    value: '(' },
  { type: 'number',   value: '4' },
  { type: 'operator', value: '-' },
  { type: 'number',   value: '1' },
  { type: 'paren',    value: ')' },
]
```

### Tabela de precedência

```javascript
const PRECEDENCE = { '+': 1, '-': 1, '*': 2, '/': 2, '%': 2, '^': 3 };
const RIGHT_ASSOC = new Set(['^']);
```

### Fluxo do Shunting-Yard

```
Para cada token:
  número    → saída direta para fila RPN
  função    → empilha no stack de operadores
  operador  → desempilha para RPN enquanto topo tiver precedência ≥ (ou > se direita), depois empilha
  (         → empilha
  )         → desempilha para RPN até encontrar (, descarta o (
Ao final     → desempilha tudo para RPN
```

### Regex para tokenize

```javascript
const TOKEN_RE = /(\d+\.?\d*|\.\d+|[+\-*\/^%()]|[a-z]+)/gi;
```

### Constantes PI e E nos tokens

Os botões `π` e `e` inserem `PI` e `E` na expressão. O `tokenize` deve converter esses tokens em seus valores numéricos (`Math.PI`, `Math.E`) antes de processar.
