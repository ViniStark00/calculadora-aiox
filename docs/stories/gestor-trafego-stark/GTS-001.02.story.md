# GTS-001.02 — Arquivos de Dados

## User Story

**Como** agente do squad `gestor-trafego-stark`,
**quero** ter acesso a um `data/clientes.yaml` único e completo com todos os clientes
de ambos os gestores, e a um `thresholds-por-especialidade.yaml` consolidado,
**para que** eu possa buscar configurações de qualquer cliente sem acessar squads externos
e classificar métricas com thresholds corretos por especialidade médica.

---

## Contexto

Este é o arquivo de dados central do squad. Dois problemas precisam ser resolvidos:

1. **Clientes duplicados:** Dr. Laureano Filho e Dra. Nicolli existem nos dois squads.
   Decisão arquitetural (DESIGN.md ADR-01): campo `gestores` é array `[vinicius, gustavo]`.

2. **Thresholds divergentes:** Vinicius usa YAML com faixas saudavel/atencao/critico;
   Gustavo usa MD com alerta/pause e categorias extras (kill-switch, frequência por tipo).
   Decisão (DESIGN.md ADR-06): adotar o threshold mais conservador; formato YAML estruturado.

Fontes dos dados:
- Clientes Vinicius: `squads/gestor-trafego-vinicius/config/clientes-config.yaml` (local)
- Clientes Gustavo: `squads/gestor-trafego-gustavo/data/clientes.md` (GitHub — via `gh api`)
- Thresholds Vinicius: `squads/gestor-trafego-vinicius/data/thresholds-especialidade.yaml` (local)
- Thresholds Gustavo: `squads/gestor-trafego-gustavo/data/thresholds-por-especialidade.md` (GitHub)

### data/thresholds-por-especialidade.yaml

**Cobertura de especialidades:**
- [ ] Contém pelo menos 15 especialidades cobrindo todos os clientes ativos
- [ ] Especialidades obrigatórias: `cirurgia_plastica`, `cirurgia_facial`, `cirurgia_corporal`, `mommy_makeover`, `cirurgia_trans`, `dermatologia`, `medicina_estetica`, `tricologia`, `oncologia`, `saude_geral`, `cirurgia_ortognatica`

**Por especialidade (campos obrigatórios):**
- [ ] Cada especialidade tem `cpl` com sub-campos `saudavel.max`, `atencao.min`, `atencao.max`, `critico.min`
- [ ] Cada especialidade tem `cpm` com os mesmos sub-campos
- [ ] Cada especialidade tem `ctr` com sub-campos `saudavel.min`, `atencao.min`, `atencao.max`, `critico.max`
- [ ] Cada especialidade tem `frequencia` com sub-campos `saudavel.max`, `atencao.min`, `atencao.max`, `critico.min`

**Seções especiais:**
- [ ] Seção `kill_switch` com threshold de spend 3 dias por especialidade
- [ ] Seção `frequencia_por_tipo_campanha` com tipos TOFU, MOFU, BOFU, AWARENESS e DEFAULT
- [ ] Cada tipo de campanha tem `alerta` e `pause` definidos
- [ ] Seção `quando_nao_alertar` com pelo menos 5 regras explícitas (incluindo: campanha_nova, spend_baixo, impressoes_baixas, awareness_cpm, laureano_meta)

- [ ] CPM de medicina_estetica: `critico.min` <= 28
