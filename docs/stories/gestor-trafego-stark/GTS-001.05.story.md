# GTS-001.05 — Agentes Tier 1 Grupo B (Monitoramento e ClickUp)

## User Story

**Como** stark-chief executando rotina-diaria ou rotina-semanal,
**quero** agentes especializados que monitoram métricas de todas as contas, escrevem
status reports no ClickUp e verificam o inbox de tarefas,
**para que** os gestores recebam alertas acionáveis diariamente e os relatórios de
status sejam escritos automaticamente sem esquecer nenhuma conta.

---

## Contexto

Estes 3 agentes têm base no squad Gustavo. Devem ser **reescritos do zero** com extensões:

- **alerta-monitor**: referencia `data/clientes.yaml` (não `data/clientes.md`); usa fallback
  para Reportei quando `meta_ad_account_id` é null; disponibiliza `metricas_coletadas`
- **clickup-writer**: suporta ambos os gestores (doc "Status Report - Vinicius" e "Status Report - Gustavo")
- **task-monitor**: referencia `data/clientes.yaml`

## Notas para Implementação

**Lógica de fallback do alerta-monitor:**
```
Para cada cliente em data/clientes.yaml onde ativo: true:
  SE excluir_meta_monitoring: true → pular (registrar como exclusão no output)
  SE meta_ad_account_id NÃO null:
    → GET /{meta_ad_account_id}/insights (Meta Ads MCP)
  SENÃO:
    → GET /{reportei_project_id}/metrics (Reportei MCP)
    → Métricas disponíveis: spend, conversas, cpl (CPM/CTR/frequência NÃO disponíveis via Reportei)
    → Alertas possíveis: apenas CPL (sem alerta de CPM/CTR/freq para esses clientes)
```

**Importante para metricas_coletadas:**
Este dict é o contrato entre `alerta-monitor` (produtor) e `coletor` (consumidor).
O formato deve ser exatamente o descrito em GTS-001.04 notas de implementação.
O coletor só reutiliza dados se `coletado_em` for da mesma semana de trabalho.

**Para clientes Vinicius sem meta_ad_account_id:**
O alerta-monitor fará fallback para Reportei. CPM e CTR não estarão disponíveis.
O output deve indicar claramente: "ℹ️ {cliente} — CPL R$X (Reportei). CPM/CTR/freq não disponíveis (sem conta Meta configurada)."

**Sobre o clickup-writer:**
A diferença entre os dois docs alvo:
- "Status Report - Gustavo": clientes da carteira Gustavo (11 clientes)
- "Status Report - Vinicius": clientes do bloco Vinicius
Para clientes `gestores: [vinicius, gustavo]` (Dr. Laureano, Dra. Nicolli):
→ escrever no doc do gestor que acionou a rotina, ou perguntar se não estiver claro.

Esta story pode ser implementada em paralelo com GTS-001.03 e GTS-001.04 (ambas na Fase 2).
