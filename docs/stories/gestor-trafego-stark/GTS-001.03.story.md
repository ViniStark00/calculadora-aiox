# GTS-001.03 — Agentes Tier 0 e Tier 2

## User Story

**Como** gestor de tráfego,
**quero** um ponto de entrada único (`stark-chief`) que roteia qualquer comando operacional
para o agente certo, e um gate de qualidade (`validator`) que bloqueia outputs incompletos,
**para que** eu não precise saber qual agente acionar — apenas digo o que quero fazer.

---

## Contexto

O `stark-chief` é a fusão de dois orquestradores existentes:
- `relatorio-chief` (Vinicius): lógica de resolução de cliente, modo multi-cliente paralelo, suporte a "todos os clientes"
- `gestor-chief` (Gustavo): routing por keyword, 3 comandos, tom direto e operacional

O `validator` é expandido do validator do Gustavo:
- Gates existentes: `gate_clickup`, `gate_reportei`, `gate_alertas`
- Gate novo: `gate_sheets` (DESIGN.md seção 4)

**Ambos escritos do zero** — não copiar os arquivos originais.

Referências de conteúdo:
- `squads/gestor-trafego-vinicius/agents/relatorio-chief.md` (local)
- `squads/gestor-trafego-gustavo/agents/gestor-chief.md` (GitHub)
- `squads/gestor-trafego-gustavo/agents/validator.md` (GitHub)

## Critérios de Aceite

### agents/stark-chief.md

**Identidade:**
- [ ] `tier: 0`
- [ ] `squad: gestor-trafego-stark`
- [ ] Saudação inicial lista os 7 comandos disponíveis

**7 Comandos:**
- [ ] `*rotina-diaria` → `tasks/rotina-diaria.md` (alertas + inbox)
- [ ] `*rotina-semanal [cliente]` → `tasks/rotina-semanal.md` (pipeline 6 fases)
- [ ] `*planilha [cliente]` → `tasks/fetch-metrics.md` + `tasks/verify-fill.md`
- [ ] `*relatorio-reportei [cliente]` → `tasks/generate-report.md` + `tasks/publish-timeline.md`
- [ ] `*status-report-clickup [cliente]` → `tasks/preencher-clickup.md`
- [ ] `*monitorar-contas` → `tasks/monitorar-contas.md`
- [ ] `*monitor-tarefas` → parte de `tasks/rotina-diaria.md`

**Routing rules (mínimo 3 keywords por comando):**
- [ ] `rotina-diaria`: "monitor hoje", "monitora hoje", "rotina diária"
- [ ] `rotina-semanal`: "rotina semanal", "pipeline", "roda tudo"
- [ ] `planilha`: "planilha", "sheets", "preenche planilha"
- [ ] `relatorio-reportei`: "relatório", "relatorio", "reportei"
- [ ] `status-report-clickup`: "status report", "clickup", "preenche clickup"
- [ ] `monitorar-contas`: "monitora", "alerta", "monitorar contas"
- [ ] `monitor-tarefas`: "inbox", "tarefas", "tasks"

**Resolução de cliente:**
- [ ] Busca em `data/clientes.yaml` (não em `config/clientes-config.yaml`)
- [ ] Passo 1: match exato por `nome` (case-insensitive)
- [ ] Passo 2: match exato por `slug`
- [ ] Passo 3: fuzzy match com threshold 0.60
- [ ] Passo 4: lista clientes disponíveis filtrados por gestor e aguarda escolha
- [ ] Ao resolver, carrega `gestores[]` do cliente para decidir quais fases do pipeline executar

**Modo multi-cliente:**
- [ ] "bloco Vinicius" / "todos os clientes Vinicius" → filtra `vinicius in gestores AND ativo: true`
- [ ] "carteira Gustavo" / "todos os clientes Gustavo" → filtra `gustavo in gestores AND ativo: true`
- [ ] "todos" / "todos os clientes" → todos com `ativo: true`
- [ ] Modo multi-cliente usa estágios paralelos (estágio coleta → estágio geração → estágio publicação)

**Princípios obrigatórios:**
- [ ] NUNCA executa lógica de domínio — apenas roteia
- [ ] SEMPRE aguarda gate do validator antes de entregar output final
- [ ] FASE 2 (sheets) só é incluída no pipeline quando `vinicius in cliente.gestores`

**Erros tratados:**
- [ ] Cliente não encontrado: lista clientes disponíveis
- [ ] Token inválido (401): "Atualizar variável de ambiente correspondente"
- [ ] Quality gate FAIL: exibe itens com problema e aguarda ação

### agents/validator.md

**Identidade:**
- [ ] `tier: 2`
- [ ] `squad: gestor-trafego-stark`
- [ ] Descrição: "Gate de qualidade. Verifica outputs antes da entrega ao gestor."

**gate_sheets (NOVO — 7 critérios):**
- [ ] `fill_sheets.py retornou exit code 0`
- [ ] `Número de linhas preenchidas bate com count de clientes ativos do bloco Vinicius em data/clientes.yaml`
- [ ] `Período: segunda a domingo da semana anterior`
- [ ] `Nenhum campo obrigatório vazio (zeros válidos; strings vazias não)`
- [ ] `Colunas obrigatórias preenchidas para cada cliente conforme sheet_columns em data/clientes.yaml`
- [ ] `Nenhum valor estimado — origem dos dados confirmada pelo script`
- [ ] `Aba da semana existe na planilha (formato DD/MM/AAAA = domingo da semana)`

**gate_reportei (do squad Gustavo — manter intacto):**
- [ ] `report_id confirmado na resposta do MCP`
- [ ] `timeline_event_id confirmado na resposta do MCP`
- [ ] `HTML do marco contém: spend, leads, CPL, CTR, CPM`
- [ ] `Período correto no título do relatório e marco`
- [ ] `Nenhuma tag HTML aberta sem fechar`

**gate_alertas (do squad Gustavo — adaptar contagem):**
- [ ] `Todas as contas cobertas (ou explicação de exclusão)`
- [ ] `Cada alerta 🔴🟡 inclui threshold de referência explícito`
- [ ] `Cada alerta inclui evidência quantitativa (valor atual vs threshold)`
- [ ] `Nenhum alerta sem lookback 3+ dias ou spend < R$20`
- [ ] `Seção ✅ SEM ALERTAS listando clientes sem ocorrência`
- [ ] `Nenhuma recomendação de ação de campanha (NOTIFY only)`

**gate_clickup (do squad Gustavo — manter intacto):**
- [ ] `Todos os campos obrigatórios preenchidos (spend, impressions, reach, frequency, CTR, CPM, leads, CPL)`
- [ ] `Período e data de geração indicados`
- [ ] `Confirmação de escrita no ClickUp com task ID retornado`
- [ ] `Sem valores estimados ou vazios`
- [ ] `CPL indicado como '-' se leads = 0`

**Comportamento PASS/FAIL:**
- [ ] PASS: "✅ GATE PASS — {tipo} — {cliente/escopo}" e libera para entrega
- [ ] FAIL: "❌ GATE FAIL — {tipo} — {cliente/escopo}" com lista numerada dos itens com problema
- [ ] FAIL: retorna ao agente responsável com lista exata (nunca modifica o output)
